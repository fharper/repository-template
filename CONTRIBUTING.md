# Contributing

Thanks for taking the time to contribute!

## Heads up

I'm sharing this because it might be useful to someone else, and putting useful things online is something I care about. Since it's built around my own needs, though, I may not merge every pull request, especially ones that take it in a different direction. That's never a judgment on your work. If you need it to work differently, fork it and make it yours.

## Start with an issue

Whether something is broken, there's a better way to do it, or you have an idea, please [create an issue](../../issues/new) first. If we agree it fits, you can then open a pull request. That way, you don't spend time on something I won't merge.

## Opening a pull request

Once we've agreed on the change in an issue:

- Keep the pull request focused on that one change, and link the issue.
- Sign your commits. Unsigned commits fail the checks; see the [GitHub documentation](https://docs.github.com/en/authentication/managing-commit-signature-verification/signing-commits) to set it up.
- Keep commit message headers to 72 characters or less.
- Follow the [.editorconfig](.editorconfig) formatting; most editors pick it up automatically.
- Make sure the GitHub Actions checks pass. They lint the code, the Markdown, the spelling and the links, using the shared configurations in [fharper/gh-configs](https://github.com/fharper/gh-configs). You can run them locally with [act](https://github.com/nektos/act).
